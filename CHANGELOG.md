## [Unreleased]

- **[TLY-79](https://github.com/gezmodean-wow/tally/issues/79) — data-spine session parse cache.** Second build-out commit off [#77](https://github.com/gezmodean-wow/tally/issues/77). Still additive — no view consumes it yet; verifiable via the new `/tally spine` command.
  - **`Spine/ParseCache.lua` (`ns.Spine.ParseCache`).** Parses each available sibling source's saved-variables exactly once via its registered `getEntriesFn` (the pure parse path — no ledger writes), caching the entry lists in memory for the session. `Begin()` enumerates `ns.Ledger:GetSources()` for sources with a `getEntriesFn` that pass `IsSourceAvailable`, then steps one source per `C_Timer` tick (`STEP_DELAY` 0.05s) — `currentSource`/`fireUpdate` announced *before* each blocking parse so a progress bar can repaint "Parsing &lt;source&gt;…" first (the per-source TSM block stays a single freeze; stepping source-by-source bounds it and gives the bar a checkpoint between sources). A `generation` counter guards in-flight timer callbacks so a `Refresh()` mid-parse cannot leave two step chains running. Listener API (`RegisterListener`/`UnregisterListener`) mirrors `ns.Synthesis` for the Commit-3 loading bar. Reads: `IsReady`, `GetState`, `GetEntries(source)`, `GetAllEntries` (flat concat, memoized once `ready`), `Summary` (for diag). `Ensure()` is the lazy entry point — kicks a parse if idle, reports whether data is ready now.
  - **Lazy population, not login-eager.** Deliberately *not* hooked into `PLAYER_LOGIN`. The alpha18 rewrite exists to kill the per-login parse tax (flipper testers relog 20-60×/session); an unconditional login parse would re-create it. The cache populates on first demand instead — a relog without opening Tally costs nothing; opening Tally pays one parse behind a progress bar. Matches toeknee's [#76](https://github.com/gezmodean-wow/tally/issues/76) Q8 answer (a 2-3s pause "when opening a detailed view" is fine *if a loading bar shows*). The auto-trigger wires into the view layer in a later commit.
  - **`TallyDB.spine.enabled` escape-hatch flag** (default on). `IsEnabled`/`SetEnabled`; `Begin` no-ops when off.
  - **`/tally spine` slash subcommand (`Core.lua`).** `parse` re-parses and opens the readout (via a one-shot listener) when the cache settles; `status` (default) opens the current readout as a copy dialog — parse phase, per-source row counts, and once ready the `Dedup.run` recompute summary (parsed entries → unified records, cross-source merges, flagged-for-review count) and stored-override count; `on`/`off` toggle the flag. New `spineFormatReport`/`spineCopyDialog` helpers alongside the other diag formatters.

- **[TLY-80](https://github.com/gezmodean-wow/tally/issues/80) / [TLY-79](https://github.com/gezmodean-wow/tally/issues/79) — data-spine pure core.** First build-out commit off the [#77](https://github.com/gezmodean-wow/tally/issues/77) projection-layer redesign — the dedup/merge core, additive and inert until the parse cache wires it up (Commit 2+). Two new files under a new `Spine/` directory; the only existing-file change is two `tally.toc` load lines after `Sources/Journalator.lua`.
  - **`Spine/Dedup.lua` (`ns.Spine.Dedup`).** Pure recompute-on-parse dedup/merge — no SavedVariables, no events, no globals. `coarseKey(e)` buckets entries on `kind | itemID | charKey | count | counterparty` (counterparty from `meta.otherPlayer`/`meta.partner`; `unknown`-kind rows fold in their entry id so each stays a 1-row cluster). `cluster(entries)` runs a two-stage pass: bucket by coarse key, then a greedy windowed pass with the `clusterGroup` source-uniqueness gate ported from `Ledger.lua` — a cluster holds at most one row per source, so distinct same-source events never collapse. Price is deliberately *not* a key field (keying on exact price would split the records whose prices disagree and hide the conflict); instead `pricesMergeable` gates pairing on a tolerance band (`PRICE_MERGE_REL` 15% / `PRICE_MERGE_ABS` 1s floor) — inside the band rows merge, outside they stay distinct. `merge(cluster)` ports `buildReconciledRecord`'s per-field Authority pick + meta shallow-merge (reuses `ns.Ledger:GetAuthority`, not a copy) and adds a conflict scan: a numeric field two sources disagree on is logged to `record.conflicts` with `record.review = true`, while the Authority pick is still kept so totals never block on a human. `entryKey(record)` derives a relog-stable id from the sorted original source-row ids. `run(entries)` returns records + a diag summary (`entries`/`records`/`merged`/`review` counts). Tuning constants (`MERGE_WINDOW`, the price band) exposed on the module — starting values mirror Reconcile's, flagged for validation against real tester data.
  - **`Spine/Overrides.lua` (`ns.Spine.Overrides`).** The one piece the spine persists — sparse manual dedup/merge corrections, bounded by human attention not trade volume, so it can't reintroduce the constant-pool wall. New `TallyDB.merge = { version = 1, overrides = {} }` sub-key (no `.toc` SV change — `TallyDB` is already registered). Overrides are keyed on `Dedup.entryKey` values so they survive a relog. CRUD (`Get`/`Set`/`Remove`/`All`/`Count`) with kind validation — `field` (replace a merged field + clear the conflict it resolves), `ignore` (drop a false-positive merge), `merge`/`split` (escape hatches; data shape accepted now, resolving engine + UI later). `Apply(record)` post-processes a `Dedup.merge` record: a `field` override replaces the value, stamps `provenance[field] = "override"`, and clears the resolved conflict (recomputing `review` from any that remain); `ignore` returns nil so the caller omits the record. Version mismatch resets rather than migrating, per the alpha expendable-data rule.

- **[TLY-72](https://github.com/gezmodean-wow/tally/issues/72) — Appearance tab.** New `UI/AppearancePage.lua` registers an "Appearance" tab (`ns.UI.CreateAppearancePage`, wired in `Core.lua` after Settings) whose body is the shared Cogworks appearance primitive called with `{ cog = "Tally" }`. Adopts the suite-wide convention from cogworks#71: UI scale + theme are suite-wide, font scale + font family are per-cog-overridable, all writes flowing through Cogworks into `CogworksSharedDB`. The builder call prefers `cw:CreateAppearanceTab` and falls back to `cw:CreateUIScalingSettingsBlock` so a stale vendored v0.14.1 lib still renders the tab; the block is re-anchored left+right to the page so it tracks tab width (the primitive sizes itself off `parent:GetWidth()` at build time, before MainFrame has anchored the page). `.pkgmeta` Cogworks external bumped `v0.14.1 → v0.14.2` to pick up the `CreateAppearanceTab` alias. First task landed off the [#77](https://github.com/gezmodean-wow/tally/issues/77) projection-layer redesign umbrella.

## [v0.1.0-alpha19]

Restoring sibling-source import and historical archive coverage on top of alpha18's active-only baseline. Two structurally distinct flows under one TLY-71 umbrella: a chunked import controller for live backfill (Flow A) and an on-demand period-synthesis engine for archive gaps (Flow B). Plus the alpha18 follow-ups — TLY-69 multi-source gold authority closes Toeknee's 63M toon-gold gap, TLY-70 chat-output consolidation moves every player-visible string off `print()` onto `ns.Output`'s channel router, and the warband row split removes the "warband total looks wrong" UI bug from TLY-68.

- **[TLY-71](https://github.com/gezmodean-wow/tally/issues/71) Flow A — manual import controller.**
  - **Setup wizard Steps 4+5 (`UI/SetupWizard.lua`).** Two new steps register conditionally — fresh installs with no sibling adapter loaded keep alpha18's 3-step flow. Step 4 surfaces per-source checkboxes for each importable sibling adapter (excludes Native; gates on `Ledger:IsSourceAvailable`), reads `:ProbeMetadata()` once on first entry into `state.probes`, and offers a window selector (30d / 90d / 12mo / all, default 12mo). Step 5 surfaces budget + delay numeric inputs with three pace preset radios (gentle 5k/3s, balanced 10k/2s, aggressive 25k/1s) and a live estimate line ("Estimate: ~3m 20s for 47,213 rows across 2 sources"). `C_Timer.After(0.05)` defers the multi-second TSM-CSV block-probe so the "scanning…" label paints first. State plumbing additions: `windowMonths`, `pace`, `budgetRows`, `delaySec`, `probes`; new helpers `detectImportableSources`, `runProbes`, `estimateRows`, `estimateSeconds`, `formatProbeSummary`, `formatDuration`; `state.refreshEstimate` as the cross-step refresh closure installed by Step 5 and called from Step 4's checkbox + window-radio handlers.
  - **Import driver state machine (`Util/Import.lua`).** New `ns.Import` module — singleton controller wrapping `Ledger:InsertManyChunkedRouted` in an outer cycle loop so the player gets pause/resume/budget-tune mid-flight. State machine: `idle → configured → running ⇄ paused → flushing → done` (with `cancelled` / `errored` exits). Each cycle slices `budgetRows` entries from the current source's parsed list and routes them through the existing 500-row / 5ms inner walk; on slice completion the outer timer sleeps `delaySec` before scheduling the next cycle. Pause cancels the outer timer; the in-flight inner chain runs to completion (~50ms max for a 10k slice) before the cycle's `onDone` observes the new phase and stops scheduling. Persistence via `TallyDB.import.pending = { version, phase, config, sourceQueue, current, results, startedAt, pausedAt, error }` — `entries[]` is NOT persisted (would be MB for big TSM CSVs); on Resume we re-parse from the sibling SV and seek to the persisted cursor. Append-only sibling logs make this safe; defensive fallback restarts the source from `idx 0` if rows shrank since the pause point. Wizard `onComplete` calls `Import:Start({sources, windowMonths, budgetRows, delaySec})` when at least one importable source is enabled; success toast branches `"Backfill running in the background — manage via /tally import"` vs `"capturing live"`. PLAYER_LOGIN's 7s deferred restore (`Core.lua` line ~261) calls `Import:RestorePending()` if `HasPending()` — TLY-71 design choice: never auto-resume on login. The player opts in via the control widget's Resume button (or `/tally import resume`).
  - **`/tally import` slash subcommand (`Core.lua`).** `status` renders a copy-dialog with phase, sources queued/done, current source progress, totals, error if any — paste-ready for issue reports. `pause` / `resume` / `cancel` flip phase + emit a brief toast. `budget <rows>` / `delay <sec>` live-tune the cycle, takes effect on the next cycle without restart. Bare `/tally import` opens the control widget when a controller exists; falls back to copy-dialog status when idle. Known v1 limitation: first-cycle source parse blocks the input thread for 2-3s on big TSM CSVs (90k+ rows); the 2s outer delay between Start and first `_step` gives the wizard close + toast time to render before the freeze.
  - **Persistent control widget (`UI/ImportControl.lua`).** Singleton draggable always-on-top panel listener-wired to `ns.Import` via `RegisterListener`. Per-source rows with state-coloured progress bars (queued / importing / done / error / skipped / paused), idx/total + percent + cadence-derived ETA. Editable numeric inputs for budget + delay commit on Enter or focus-lost via `Import:UpdateBudget`. Pause / Resume / Cancel buttons mirror `controller.phase`. Title bar `[_]` minimises to a 28px badge near the minimap (showing the current source's percent), click-to-restore; `[X]` is the same as the Cancel button — a `StaticPopup` confirm that preserves pending state ("Stop and resume later," not "throw away progress"). Position persisted at `TallyDB.ui.importController` with separate expanded/minimised positions and a mode flag. Auto-fades 6s after `phase == "done"`; stays visible on `cancelled` / `errored` so the player can read the result and Resume. Show entry points: wizard `onComplete` after `Import:Start`, PLAYER_LOGIN restore after `Import:RestorePending`, `/tally import` (bare) and `/tally import resume`.
- **[TLY-71](https://github.com/gezmodean-wow/tally/issues/71) Flow B — on-demand period synthesis.**
  - **Synthesis engine (`Util/Synthesis.lua`).** New `ns.Synthesis` module — singleton job model with the same state machine as `ns.Import` (`idle → running ⇄ paused → done / cancelled / errored`) so a future shared "long-running job" widget could subscribe to both. `EnsurePeriods(keys, opts)` is the main entry point: for each requested period key (YYYY-MM), gathers cached sibling-source entries, dedupes by entry id (same shape as `Archive:Save`'s `byId` map), and writes via `Archive:Save`. Source parsing is the expensive step (~2-3s for a big TSM CSV); the job holds a per-source cache so a 24-month run pays the parse cost once. Per-source entries are bucket-sorted by `date("%Y-%m", atTime)` so subsequent periods become O(1) bucket fetches rather than O(N) scans. One period per outer cycle with configurable `delaySec` (default 0.5s) so the player can Pause/Resume between periods even on small jobs. `GetCandidates(opts)` partitions candidate months into already-archived / missing / current-month (current-month is skipped — that's the active set's job, not the archive's) by reading `ProbeMetadata.byMonth` from each adapter. Per-period success toast unless `opts.quiet`; final completion toast summarises rows + period count. State NOT persisted across logout (synthesis is short enough that "click the button again" is fine).
  - **Archive LRU eviction (`Archive.lua`).** `archiveIndex[key].lastAccessedAt` is now stamped on `Save` + `Load`. `resolveSlot` layers three tiers when the existing key has no slot: (1) reuse a slot from `TallyDB.ledger.freedSlots` (entries `Delete()`d earlier), (2) advance `nextSlot` if still under `SLOT_COUNT`, (3) evict the LRU archive — `findLRUKey()` walks `archiveSlots` keys and picks the lowest `lastAccessedAt` (missing values treat as oldest so pre-LRU archives migrate cleanly). `Delete()` pushes the freed slot number onto `freedSlots` so a clear-source-then-backfill sequence reuses the explicit free before resorting to LRU eviction. Evicting an archive also drops it from the in-memory LRU(3) cache to avoid stale-data reads after the slot global is cleared. The 60-slot pool now runs in steady-state recycle mode indefinitely without bumping `SLOT_COUNT`.
  - **`/tally synth` slash (`Core.lua`).** `start` (or no arg) synthesises every missing period siblings cover (skips current month + periods that already have archives). `status` opens a copy-dialog; when idle, also surfaces the coverage probe ("18 missing, 4 already archived") so the player sees what would run without committing. `pause` / `resume` / `cancel` flip phase + emit a toast.
  - **Synthesise history button (`UI/SynthButton.lua`).** Reusable button factory `ns.UI.CreateSynthButton(parent)`. Tooltips with live coverage probe (missing periods, ~row estimate, source list, current-month notice — read off `Synthesis:GetCandidates` via `ProbeMetadata.byMonth` so the tooltip stays cheap, no full sibling parse). Click → confirm `StaticPopup` with period count + total-rows estimate + "first parse can block for a few seconds on big TSM CSVs" warning → `Synthesis:EnsurePeriods` kicks off. Listens to `ns.Synthesis` state and disables itself + relabels to "Synthesising…" / "Synth paused" / "Flushing…" so all three pages reflect the same singleton job. Re-enables on done/cancelled/errored. Anchored: Research (right of "View lifecycle →"), Lifecycle (right of FIFO/Avg cost-basis toggle), Compare (right edge of toggle row — deliberately next to "Include archives (slow)" so the read-vs-write pairing is visible).
- **[TLY-69](https://github.com/gezmodean-wow/tally/issues/69) — multi-source gold authority.** Inventory-side gold-source registry; `preferredCharGold(charKey)` walks the registry and picks the freshest `moneyAt`. Sources for v1: `tally-native` (alpha18 capture), `syndicator` (rollup `lastFullScan` as freshness proxy since the API has no per-char timestamp), `tsm` (parses `TradeSkillMasterDB.s@<char> - <faction> - <realm>@internalData@goldLog` CSV — `minute,copper\n<minute>,<copper>\n...`, last row gives most recent balance + timestamp). `/tally diag gold` grows per-source columns + a chosen-source provenance column. Closes the path Toeknee's 63M toon-gold gap was sitting on (27/68 characters reporting 0 gold because they hadn't logged in since Syndicator+Tally were installed — TSM Accounting's goldLog covers them).
- **[TLY-70](https://github.com/gezmodean-wow/tally/issues/70) — output-channel taxonomy.** Six commits across alpha19 (`c205ae2` cohort 1 router + first migrations, `a8bdd8e` cohort 2 UI prints, `37b0715` cohort 3 Core slash handlers, `e523b48` cohort 4 small-module status, `19a7211` cohort 5 NetWorth:PrintSnapshot Format/Print split, `13e3e58` taxonomy refinement). Chat output (`/tally networth`, explicit opt-ins) goes via `ns.Output:ChatRaw` so every chat line mirrors to the debug log automatically — `/tally debug` becomes the always-copyable archive even when chat-frame filters block selection. `/tally diag chat` + `/tally research-chat` rerouted to copy-dialog (diagnostic content belongs in inspectable substrate). Seven documented exceptions remain (pre-Cogworks init, defensive fallbacks, vendored libs).
- **[TLY-68](https://github.com/gezmodean-wow/tally/issues/68) follow-up — `ae00460` warband row UI split.** `UI/NetWorthPage.lua`'s "Warband" row used to show `warband.total` (gold + items combined) as the row's headline figure. ## [v0.1.0-alpha18]

The architecture rewrite, phase 1 — active-only baseline. alpha13 and alpha16 were both haunted by the same root cause: account-wide TallyDB grows with row count, hits Lua's per-chunk constant-pool cap (2^18 entries), and the entire SV file fails to load wholesale. alpha14's compressed blob and alpha16's multi-SV slot architecture each pushed the wall further out without removing it. The wall is gone now: the active blob lives in its own SV (`TallyActive`), TallyDB holds nothing that grows with row count, and the constant-pool overflow can't recur from a fattening active set.

This is also a deliberate scope retreat. The pre-rewrite Tally tried to be the universal repository for transaction history — re-importing TSM / FlipQueue / Journalator on every PLAYER_LOGIN, dirtying the active blob with a session marker, paying a per-login tax that scaled with total ledger size. The flipper-loop stress case (20-60 character logout/login cycles per session, ~4-5 minutes per character) made that 60× tax unaffordable. The new framing: **sibling sources keep their own permanent stores. Tally is the cross-source aggregation layer, not the universal repository.** Sibling import returns in alpha19 as a user-initiated, pausable, resumable wizard flow; archives become evictable caches in alpha19+; on-demand period synthesis follows.

Tester data is expendable in alpha (no migration, no grandfathering — clean break gated by `TallyDB.tally_schema_version`). Settings, history snapshots, net-worth strategy, minimap, and theme are preserved.

- **TallyActive SV split.** `tally.toc` declares `TallyActive` alongside the existing `TallyA001`..`TallyA060` archive slot SVs. `Ledger:SaveToDisk` writes `_G.TallyActive` (single deflated string constant); `loadFromDisk` reads from it. TallyDB's chunk no longer holds anything keyed off row count — the structural fix for the alpha13/alpha16 overflow regression. `Ledger:Clear` nils `_G.TallyActive` so `/tally reset` actually clears the active blob too.
- **alpha18 schema gate (`Core.lua`).** Two markers, deliberately split:
  - **Account-wide** (`TallyDB.tally_schema_version`) — fires once per account. Wipes `TallyDB.ledger`, nils every `_G.TallyA001..TallyA060`, nils `_G.TallyActive`, resets `TallyDB.setup` + `TallyDB.disabledSources`. Account-wide so Char2's first alpha18 login doesn't clobber rows Char1 captured between Char1's wipe and Char2's first session.
  - **Per-character** (`TallyCharDB.tally_schema_version`) — fires once per character. Clears `TallyCharDB.tallyAcknowledged` so each character sees the welcome wizard once if account-wide setup hasn't been completed yet.
- **PLAYER_LOGIN strips auto-import + legacy-blob migration kick.** The `C_Timer.After(5, function() ... :ImportFromAllSources() end)` block that drove the per-login sibling-source backfill is removed; the alpha14/15 → alpha16 legacy-blob detect / `KickLegacyLoad` / `StartMigration` pipeline is removed. Both are dead under alpha18 — the wipe gate clears their source data fields. PLAYER_LOGIN is now: history prune, register Syndicator callbacks, capture char gold (TLY-68), open session log, register source adapters, register UI pages, auto-show welcome wizard. No per-row work.
- **Welcome-only setup wizard (`UI/SetupWizard.lua`).** Six steps collapse to three: Welcome / Pricing Strategy / History. Sources, Concept Primer, and Backfill steps are removed. Welcome copy explains alpha18 reset + that capture starts fresh from this login. `onComplete` flips `TallyDB.setup.completed = true` without triggering any sibling-source import. The `PACE_PRESETS` pace-radio table, the `MultiProgress` panel hookup, the `ImportFromAllSourcesChunked` callbacks, and ~420 lines of removed step builders + dead-code helpers go with it.
- **`Ledger.loadFromDisk` simplification.** The three-shape migration handler (modern `TallyDB.ledger.active` blob / alpha14/15 single-blob / pre-alpha14 raw entries) collapses to a single `_G.TallyActive` read with a `defaultMem()` fallback. Schema-version unchanged at 1; the TallyActive split is structural, not a row-shape change.
- **TLY-68 — Tally captures char + warband gold via real-time WoW events.** Stops Tally from being 100% dependent on Syndicator's snapshot for gold accounting. Lines up with TLY-31's "Tally as source of truth" direction — gold is the next domain after ledger.
  - `Inventory:CaptureCurrentCharGold` writes `TallyDB.charGold[charKey] = { money, moneyAt }` from `GetMoney()` at PLAYER_LOGIN and on every `PLAYER_MONEY` event. Account-wide map keyed by Cogworks "Name-Realm" charKey so any character's projection can read any other character's last-captured value.
  - `Inventory:CaptureWarbandGold` writes `TallyDB.warbandGold = { money, moneyAt }` from `C_Bank.FetchDepositedMoney(Enum.BankType.Account)` when the warbank UI opens (`PLAYER_INTERACTION_MANAGER_FRAME_SHOW` with `Enum.PlayerInteractionType.AccountBanker` = 28 in retail). Falls back to `Syndicator.API.GetWarband(1).money` when the bank API isn't available on the running client.
  - `Inventory/Ownership.lua` `projectCharacter` / `projectWarbandBank` return `preferredCharGold(charKey) or data.money or 0` and `preferredWarbandGold() or data.money or 0` — Tally's captured value when present, Syndicator's snapshot as fallback for characters Tally hasn't seen log in yet under alpha18. The existing `/tally diag gold` `rollupGold` column now reflects what NetWorth actually uses, so testers can see whether Tally's capture or Syndicator's snapshot is in play per character.
- **Sibling-source metadata probe — `/tally diag sources`.** Each sibling adapter (FlipQueue, TSM, Journalator) gains a `:ProbeMetadata()` method returning `{ available, count, fromTs, toTs, byMonth, notes }` — the cheapest fidelity-preserving readout of "what an alpha19 import would have to chew." Probe walks each adapter's data once and reads only the `time` column / `postedAt` field, skipping per-row mapping.
  - `Core.lua` adds `inspectSourcesProbe` aggregator + `formatSourcesProbeReport` formatter + `sourcesCopyDialog`. Wired to the `/tally diag sources` subcommand. Output is per-source totals + 60-day window peak (worst-case sliding-window approximated as max consecutive-month sum) + per-month distribution table (newest first) + per-source notes, in a copy-dialog.
  - The 60d peak is the headline number for sizing alpha19's per-cycle row budget for the manual import controller. Starting assumption is 10k rows per cycle; tester probe data refines it. The probe is the alpha18 simulated-import substitute — active-only baseline ships without imports, testers run the probe, paste the readout into a GitHub issue, and we lock the budget against actual distributions before alpha19's manual import controller lands.
  - Probe cost is O(rows) with a single field read per row. On big-tester TSM CSVs (90k+ rows) that's a multi-second blocking pass — the diag help text flags this as one-time diagnostic work, not a recurring command.
- **Phasing follow-ups (post-alpha18).**
  - **alpha19** — setup wizard's manual import controller (pause/resume/per-cycle budget); on-demand period synthesis from view actions; LRU eviction policy when slot pool fills.
  - **alpha20+** — [TLY-66](https://github.com/gezmodean-wow/tally/issues/66) CSV-shaped slots (memory drop + export-ready format for the future offline pro service).

## [v0.1.0-alpha16]

The TLY-51 tiered-storage bundle. Closes the structural per-tab-open freeze that was hitting big-ledger accounts (zpectre 438k rows, Toeknee Compare-source-change hang on alpha15). The ledger storage shape goes from one flat compressed blob (alpha14/15) to a small mutable active set + on-demand monthly archive blobs; queries default to the active window and only touch archives when explicitly asked, so day-to-day Tally runs in O(active) regardless of total history size.

- **TLY-51 — tiered ledger storage.** Storage layout for `TallyDB.ledger` goes from `{ blob, blobMeta }` to:
  - `active`        — mutable serialised+deflated blob of the hot working set (≤25k rows / ≤60 days by default)
  - `activeMeta`    — count, savedAt, byte / timing metrics, schemaVer
  - `archives`      — `{ ["YYYY-MM" | "YYYY-MM-wN"] = { blob, count, fromTs, toTs, bytes, schemaVer, savedAt } }`
  - `archiveIndex`  — `{ [key] = { itemIDs, charKeys, kindCounts, monthlyAggregates } }`, stays resident (small)

## [v0.1.0-alpha15]

Single-issue alpha addressing TLY-50 — logout-delay perf regression introduced by TLY-49's compressed blob storage. Toeknee_atx reported on alpha14 that logout now had a multi-second UI freeze before the 20s logout countdown finished, attributable to `LibDeflate:CompressDeflate` running synchronously at level 5 over a ~98k-entry serialised payload.

- **TLY-50 — drop LibDeflate compression level 5 → 1.** LibDeflate's level 1 is the fastest setting it offers without disabling compression entirely (level 0). Per the lib docs and the implementation, level 5 trades CPU for ratio at a ~5-10x cost over level 1; the output is ~20-30% smaller. For a 98k-entry serialised payload (Toeknee's case) the level-5 compress was the dominant cost on logout — measured in seconds — while level 1 lands in tens-to-hundreds of ms. Level 1 output is still one Lua constant in the SV chunk, which is what TLY-49 needed to solve the original constant-pool overflow; the slightly larger blob is unchanged in that respect. The `LibSerialize:Serialize` step is irreducible (the lib doesn't expose a faster mode for tables of small dicts) and remains the sole pure-Lua cost on save.
- **Save-time instrumentation surfaced in `Ledger:StorageInfo()` + `/tally diag` Storage section.** New fields `serialisedBytes`, `serialiseMs`, `compressMs` populated from `debugprofilestop` deltas around each step in `Ledger:SaveToDisk`. Diag chat-print line gains `(serialise Xms + compress Yms; serialised N bytes)` annotation on the blob-last-saved row. Lets testers confirm the perf fix and gives us data for any future tuning (e.g. if `serialiseMs` itself becomes the bottleneck on multi-hundred-thousand-row ledgers).

## [v0.1.0-alpha14]

Single-issue alpha addressing TLY-49 — the structural fix for the SV constant-table-overflow that the alpha13 per-character marker only mitigated symptomatically. Toeknee_atx + _zpectre_'s alpha13 reports confirmed the popup keeps firing once per never-before-acknowledged alt and Native captures stay gated as long as `setup.completed` doesn't persist across sessions; both root-cause back to TallyDB failing wholesale Lua-load due to constant-pool overflow.

- **TLY-49 — compressed blob storage for the ledger.** WoW writes account-wide TallyDB as one giant Lua chunk; Lua's per-chunk constant-pool cap is 2^18 (262,144) entries. Big-tester ledgers (Toeknee on alpha12: 91k+ rows × multiple distinct numeric fields per row + item names + char keys + sourceKinds) push past the cap and the entire SV file fails to load wholesale — TallyDB stays nil, Tally's `TallyDB = TallyDB or {}` initialises a fresh empty table, all persisted state gone every session. Storage layer rewritten around `TallyDB.ledger.blob` — a deflated LibSerialize blob holding the entries[] + byId{} pair. One Lua constant in the SV chunk no matter how many ledger entries it represents, so the constant-pool cap is no longer in play.
  - **Vendored libs.** `Libs/LibSerialize/LibSerialize.lua` (MIT, v5, by Ross Nichols) and `Libs/LibDeflate/LibDeflate.lua` (zlib, v3, by Haoqian He). Both upstream-verbatim. Loaded in `tally.toc` after LibStub. Both register via `LibStub:NewLibrary` at file-load time and are picked up by Tally as `LibStub("LibSerialize", true)` / `LibStub("LibDeflate", true)` at the top of `Ledger.lua`.
  - **Storage refactor (`Ledger.lua:954-1085`).** `db()` rewritten as a lazy-load wrapper around module-local `_workingMem`, populated from the blob on first call via `loadFromDisk()`. All pre-existing callers (Insert, InsertMany, Query, Stats, Reconcile, Compare, ClearSource, Count, etc.) keep the same call surface — the storage layer is invisible to them. `_dirty` flag flipped by Insert / InsertMany (when actually inserted) / Clear / ClearSource (when actually removed). `Ledger:SaveToDisk()` reserialises + recompresses + writes the blob when dirty + libs available; early-exits otherwise so read-only sessions don't pay the cost.
  - **PLAYER_LOGOUT handler (`Core.lua`).** WoW saves SVs after every addon's `PLAYER_LOGOUT` returns, so the new `ns:PLAYER_LOGOUT` is the canonical "flush working memory back to disk" point. Wraps `SaveToDisk` in pcall so a serialise error can't bubble up and prevent WoW's normal save sequence.
  - **One-shot migration.** Pre-blob users land in `loadFromDisk` with `TallyDB.ledger.entries` still populated as a raw table (the legacy shape). Migration treats it as the working memory directly and marks dirty so the next save promotes it to blob form. Legacy fields stay on disk until the first successful save so a crash mid-migration leaves the old copy intact for the next session to retry.
  - **Grandfather check rewire (`Core.lua`).** Pre-fix the PLAYER_LOGIN grandfather check (line ~121) read `#TallyDB.ledger.entries` directly. Switched to `Ledger:Count()` which triggers the lazy load — the count is the same value but going through the new accessor handles the legacy → blob round-trip transparently.
  - **`/tally diag` Storage section.** New `Ledger:StorageInfo()` + `inspectStorage()` inspector + diag chat-print line. From that point on, the ledger writes back as a blob and stays loadable. New users + users below the prior overflow threshold are unaffected — the migration on first load handles them transparently.

## [v0.1.0-alpha13]

Tester-feedback bundle on top of alpha12 — three issues addressed together because TLY-32 and TLY-35 turned out to share a root cause and the alpha13 cadence rule favours bundling related hotfixes when they ship the same week.

- **TLY-32 + TLY-35 — welcome popup no longer re-fires when account-wide TallyDB fails to load.** Two testers (Toeknee_atx, _zpectre_) confirmed across alphas 8 / 10 / 11 / 12 that the welcome popup kept firing on every alt despite the alpha10/11 skip-flag plumbing. Toeknee's diag dump showed `setup.skipped = true` *was* persisting, so the gate logic itself was correct — but his recent BugSack report finally surfaced the connector: `constant table overflow in saved variables tally`. Lua's bytecode compiler caps a single function's constant pool at 2^18 (262,144) entries; WoW writes account-wide SVs as one giant `TallyDB = { ... }` literal that compiles as one chunk, and a tester with hundreds of thousands of distinct ledger rows / item names / atTime epochs / copper amounts pushes past that limit. When the parser overflows the file fails to load wholesale, `TallyDB` stays nil for the rest of the session, Tally's top-level `TallyDB = TallyDB or {}` initialises a fresh empty table, and the account-wide `setup.skipped` flag is gone. The popup re-fires on every alt because the skip flag never *survives*. Fix uses the per-character SV (`TallyCharDB`) — a separate, much smaller file that doesn't hit the overflow — as a load-failure-resistant marker. `TallyCharDB.tallyAcknowledged = true` is now written alongside the existing account-wide flags in `onCancel`, `onStepChange` (when player advances past welcome), and `startBackfill` (Finish). `ShouldShowSetupWizard` consults the per-char marker as a third short-circuit after `setup.completed` and `setup.skipped`. So even when the account-wide load fails, every previously-acknowledging character continues to suppress the auto-popup. Players new to Tally still see the popup once per character (per-char marker hasn't been set yet) — this is a deliberate trade vs the alpha11 "once per account, ever" spec, but a reliable per-character one-shot beats the broken account-wide flag for testers in the SV-overflow regime.
- **TLY-32 secondary — defensive ordering in `onCancel`.** The persistence flags (`TallyDB.setup.skipped` / `TallyCharDB.tallyAcknowledged`) now write *before* any potentially-throwing call (`print`, `RefreshLDB`, `wizardFrame:Hide()`). Previously a late error inside the handler — e.g. an `RefreshLDB` path overflowing on a tester's huge net-worth total — could leave the persistence commit unrun. The print + Hide now run under `pcall` for the same reason; the user's choice is committed before any of those can fail.
- **TLY-32 secondary — `Sources/Native/Vendor.lua:188` `%d` → `%.0f` overflow fix.** Pre-fix the vendor-close `dbg:PrintDebug` formatted `money` and `residual` (raw copper deltas) via `%d`, which throws on values > 2.1B copper (signed int32). `string.format` is evaluated by the caller before `PrintDebug` decides whether to emit, so the format throws even when the debug flag is off — every vendor close on a high-value session was a candidate Lua error. Same pattern as the TLY-33 alpha6 sweep that missed this one path. Other Native buckets (AHPosting, AHInvoice, Mail, Repair) already use `%.0f` correctly per TLY-33.
- **Note on the underlying SV-overflow root cause.** The per-character marker fix unblocks the *popup-keeps-firing* user-visible symptom, but the underlying constant-table overflow on huge account-wide TallyDBs is a real structural issue that still needs addressing — testers who hit the overflow will see no ledger / no setup state / fresh inventory rebuild every session, which silently degrades cross-cog research data. The proper fix is compressed serialisation of the ledger (LibSerialize + LibDeflate) so the SV file holds one constant string instead of hundreds of thousands of unique numbers/strings; that's a bigger refactor than fits the alpha13 hotfix window and is tracked under [TLY-49](https://github.com/gezmodean-wow/tally/issues/49) as the next-bundle work. TLY-32 stays open until that ships and an affected tester verifies a clean cross-session round-trip.
- **TLY-48 — Reconcile no longer over-merges same-source rows.** Toeknee_atx's [TLY-24](https://github.com/gezmodean-wow/tally/issues/24) divergence dump on alpha12 (`/tally diag divergence`) showed 3,481 field-disagreement clusters across 3,903 multi-source clusters, where the bulk of disagreements were *same source disagreeing with itself* — TSM rows for the same `(kind, charKey, itemID, count)` falling within 5 minutes were collapsing into one cluster, and `buildReconciledRecord`'s Authority pick was dropping every row's copper after the first match. Vendor-flurries (10 distinct stack-vendors of the same item across 30s → 1 record) and back-to-back postings (two TSM purchase rows 3s apart, copper 696g vs 796g → one 696g record, 796g lost) were the dominant patterns. Root cause: `Ledger.lua:598-616` `clusterGroup` matched on `(kind, charKey, itemID, count, atTime within 5min)` only — source-blind. Adapter-level dedup (TSM hashes on atTime+name+qty+price; each sibling adapter has its own per-source dedup) is the authoritative deduper for intra-source duplicates, so by the time two same-source rows hit the ledger they're already distinct events from that source's perspective. Reconcile is supposed to coalesce *cross-source* overlap (Native + TSM both observing one sale), not paper over distinct same-source events. Fix adds a source-uniqueness gate to `clusterGroup` via a parallel-tracked `clusterSources` set: a candidate row joins an existing cluster only if its source isn't already represented; otherwise it opens a new cluster. Returned cluster shape unchanged (the source set is local to `clusterGroup` and doesn't escape), so `buildReconciledRecord`, the divergence reporter, and Aggregator's reconciled consumers all keep working without changes. Effects: TSM-only flurries split into N single-row clusters (correct — each TSM row is a distinct event per TSM's adapter dedup); Native + TSM observing one event still coalesce into a 2-row cluster (correct cross-source dedup, unchanged); FlipQueue intra-source dupes (e.g. multiple FQ rows at the same epoch second) no longer get masked by Reconcile — those should be handled by FlipQueue adapter dedup on their own merits. After this fix Aggregator totals (`record.sales` / `record.purchases` / `record.failures` counts, `profitSummary` / `salesSummary` / `purchasesSummary` totals) move closer to TSM's totals; LedgerPage Reconciled-mode rows track real-event counts more faithfully; divergence-report field-disagreement counts drop sharply (single-source false-disagreements stop existing as clusters, so they no longer surface).

  - `Ledger.Authority` is a per-`(kind, field)` source priority table. Most importantly `sale.copper` and `purchase.copper` put TSM first because TSM's CSV records the post-cut amount precisely while Native rounds to whole copper off the mail invoice. `atTime` defaults Native first across the board (event-driven, exact second). vendor-* gives Native priority on copper too — the bag-delta + sellPrice calculation is exact, while TSM/Journalator write after the fact. `Ledger:GetAuthority(kind, field)` returns the priority list, falling back to `DEFAULT_PRIORITY` for any (kind, field) tuple without an explicit override.

  - **`Sources/Native/Repair.lua`** — `hooksecurefunc("RepairAllItems", ...)` with deferred `C_Timer.After(0.1)` money-delta sample to let the server's money packet settle.   - **`Sources/Native/Mail.lua`** — `TakeInboxMoney` hook → `mail-receive` rows for non-AH mail (filtered against `GetInboxInvoiceInfo` to avoid double-counting AH-invoice mail that AHInvoice.lua already records). `SendMail` hook + `GetSendMailMoney` → `mail-send` rows for outbound money attachments. Each bucket pre-creates its skip-counter slots in the shared table with a bucket prefix (`posting_no_deposit`, `vendor_no_sell_price`, `repair_zero_cost`, `mail_recv_invoice`, etc.) so `/tally diag` shows stable keys regardless of session activity.
