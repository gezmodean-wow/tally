## [v0.1.0-alpha11]

Tester-reported follow-up to alpha10's TLY-35 fix. Single-issue alpha per cadence (alphas between bundles are tester-feedback hotfixes; the next planned bundle stays on its own track).

- **TLY-35 follow-up — welcome popup is one-shot.** Tester report (Zong on alpha10): the popup still fired on every alt despite the alpha10 checkbox + skip-flag plumbing. Root cause was UX rather than persistence — the checkbox was easy to miss, so testers were Cancel-ing alone (which by spec re-fired next login). Per direct user direction the spec changes: the player gets two choices on the welcome step (move forward via Next, or skip via Cancel) and *either choice* permanently dismisses the auto-popup. Re-engagement is exclusively via Settings → Re-run setup wizard or `/tally setup`. Implementation: removed the "Don't show this on login again" checkbox and `state.dontShowAgain` from `UI/SetupWizard.lua`. `onCancel` unconditionally writes `TallyDB.setup.skipped = true` (idempotent against `setup.completed` to avoid clobbering on Settings re-run after a successful Finish) and prints a one-line chat reminder pointing at Settings. Added `onStepChange` that latches `setup.skipped = true` the first time the player advances past the welcome step, so a mid-flow bail (player clicked Next, then Cancel three steps deep) doesn't re-pop on the next character. Welcome step body text rewritten to spell out the two-button contract — "Click Next to start setup, or Cancel to skip. Either way, this popup won't appear again." `ShouldShowSetupWizard` comment block updated to reflect the broader meaning of `skipped` (any user dismissal, not just an explicit skip checkbox). LDB skipped-state tooltip + `inspectSetup` diag inspector unchanged — already keyed off the same `setup.skipped` flag.

## [v0.1.0-alpha10]

Closes the authoritative-ledger bundle (Phases 2–4) plus the alpha9 popup-fix slice. After alpha8 shipped Phase 1 and a stack of UI polish fixes, alpha9 was a quick TLY-35 follow-up that the user opted to fold into a single bigger drop instead of cutting separately — so this rev carries the popup fix alongside the full Schema / Unknown-routing / Reconcile / Authority / divergence-reporter workstream.

- **TLY-35 — welcome popup respects skip + LDB calm tone for skipped state.** Tester report: the first-run setup popup re-fired on every alt and on the same character multiple times even after walking through the wizard, because `TallyDB.setup.completed` only flips inside `startBackfill` (the post-Finish import kickoff). Any exit before that — Cancel button, the user logging out mid-flow, errors during a step build — left the flag unset. Fix introduces a third state via `TallyDB.setup.skipped`: a "Don't show this on login again" checkbox on the Welcome step (bound to `state.dontShowAgain`, mirrors `TallyDB.setup.skipped`), `onCancel` writes the flag from the checkbox state (true→set, false→clear so unchecking + Cancel re-enables the auto-popup), `ShouldShowSetupWizard` short-circuits on either `completed` or `skipped`, `startBackfill` clears `skipped` on completion for state hygiene. Companion fix on the LDB launcher: skipped users were still seeing the gold/yellow "setup required" tooltip + launcher text. Splits the LDB-side check into `setupPending` (still drives click → opens wizard so skipped users can re-engage) and `setupSkipped`. Skipped state gets a calm gray "setup skipped" launcher text + a 2-line tooltip pointing at Settings → Re-run setup wizard; pending-but-undecided keeps the gold "setup required" + full nag tooltip.
- **TLY-29 — capture-layer rigor: Ledger.Schema, Ledger.Kinds.Unknown, BuildUnknownEntry helper, four-adapter refactor.** New foundation in `Ledger.lua`:
  - `Ledger.Kinds.Unknown = "unknown"` — catch-all kind for adapter rows whose source-kind we don't recognize. Routed rows carry the original string in `meta.sourceKind`. `KindSign(unknown)` is 0 (neutral) — explicit fall-through with the comment block updated to call out the new case so future kinds inherit explicitly-neutral semantics. Unknown rows are queryable + diagnostic but never affect P&L.
  - `Ledger.Schema` — per-`(kind, source)` field declaration table. Living documentation: which adapter populates which canonical fields and which source-specific meta keys for which kind. Drives `/tally diag` introspection and primes the Phase 3 Reconcile pass, which needs to know per-field which sources can authoritatively supply a value. Additive — adapters keep writing the meta tables they always have; Schema describes them, doesn't replace them. Schema entries cover sale, purchase, ah-cancel, ah-expire, ah-fee, ah-deposit, vendor-sell, vendor-buy, mail-receive, mail-send, trade, repair, refund, taxi, trainer, quest-reward, loot, mission, trading-post, crafting-order-placed, crafting-order-fulfilled, and the new unknown bucket. The unknown entry intentionally has no predeclared sourceFields (by definition we don't know the shape) but mandates `meta.sourceKind` via `metaRequired`.
  - `Ledger:BuildUnknownEntry(attrs)` — adapter helper. Validates the minimum required inputs (source, sourceId, atTime, sourceKind), merges adapter-supplied meta on top of `{sourceKind = ...}`, and returns a fully-formed entry the adapter appends to its entries list. Centralizes the routing pattern.
  - **TSM (`Sources/TSM.lua`).** Pre-fix `csvSales` resolver fell back to `kind = "sale"` for any `source` value other than "Auction" or "Vendor", and `csvBuys` mirrored that with `kind = "purchase"`. TSM emits "Trade" (direct player trade reconciled into the accounting log) and reserves the source enum for future additions; both landed in the wrong bucket, inflating sale/purchase counts and tilting per-item pricing history. Resolver now returns nil for any non-Auction/Vendor src; `importCSV` routes that path through `Ledger:BuildUnknownEntry`. Hash incorporates the raw src ("unknown:Trade", etc.) to keep id collisions impossible across distinct source-kinds at the same epoch second.
  - **FlipQueue (`Sources/FlipQueue.lua`).** Pre-fix any FlipQueue log entry whose `auctionStatus` wasn't sold/collected/expired/cancelled/active silently dropped. Now routes through `BuildUnknownEntry` with `sourceKind = status`. "active" stays a deliberate skip (in-flight auction, no completed amount); empty status stays a skip; buy-price rows still emit their own purchase entry independent of status, so an unknown-status row with a buyPrice now produces two ledger entries (Unknown + purchase) matching the existing sold/cancelled-with-buyPrice two-row pattern.
  - **Journalator (`Sources/Journalator.lua`).** Pre-fix `mapFailure` dropped any row whose `failedType` wasn't expired/cancelled, and `mapVendoring` did the same for `vendorType` outside sell/buy. Both unknown paths route through `BuildUnknownEntry` with `sourceKind` = the unrecognized type (or `"(empty)"` if missing). Hash includes `unknown:<type>` plus the existing salt; meta carries `bucket = "Failures" | "Vendoring"` so consumers can see which Journalator stream produced the row. Other Journalator skip paths (bad_row_or_no_time, no_char_key, zero_or_missing_value) stay as drops — those are missing-data signals, not unknown-kind signals.
  - **Native AHInvoice (`Sources/Native/AHInvoice.lua`).** Pre-fix the scanInbox gate filtered to seller/buyer invoiceType and dropped anything else. Now passes any non-nil invoiceType to `entryFromInvoice`; recognized types still produce sale/purchase, unrecognized types route to Unknown via the formerly-dead else branch. Fee fanout (consignment companion entry from `feeEntryFromInvoice`) stays gated to `invoiceType == "seller"` since the consignment field is seller-specific by Blizzard's contract. Native/Vendor / AHPosting / Mail / Repair don't need refactor — they classify deterministically from event types.
  - **`UI/LedgerPage.lua` Unknown filter chip.** New "Unknown" chip after "Other" filters to `kind = "unknown"` so testers can isolate routed rows in one click.
- **TLY-30 — Ledger.Authority + Ledger:Reconcile with per-field provenance + consumer migrations.** Phase 3 of the bundle.
  - `Ledger.Authority` is a per-`(kind, field)` source priority table. Most importantly `sale.copper` and `purchase.copper` put TSM first because TSM's CSV records the post-cut amount precisely while Native rounds to whole copper off the mail invoice. `atTime` defaults Native first across the board (event-driven, exact second). vendor-* gives Native priority on copper too — the bag-delta + sellPrice calculation is exact, while TSM/Journalator write after the fact. `Ledger:GetAuthority(kind, field)` returns the priority list, falling back to `DEFAULT_PRIORITY` for any (kind, field) tuple without an explicit override.
  - `Ledger:Reconcile(filter)` — same call surface as `Query`; returns reconciled records. Pipeline: Query rows under filter → group by `(kind, charKey, itemID)` → cluster within an anchor-anchored 5-minute atTime window + count match → for each cluster build a record by walking the Authority priority list per canonical field (atTime, copper, count, itemKey), falling back to any-row-with-value if priority misses → meta merges in priority order → `provenance` maps every canonical field to the source that won; `metaProvenance` does the same per meta key. Single-row clusters pass through with trivial provenance. Reconciled record id = `"reconciled:" + concatenated originalIds`. Reconcile clustering is stricter than Compare's tiered matching — Compare's fuzzy tier (1h) exists to align bulk archive imports between sources whose clocks may have drifted; Reconcile is reasoning about live multi-source overlap on a single user's events, where 5min covers all observed lag. Unknown rows skip reconciliation by design.
  - Reconciled records carry a representative `source` field (whichever source won the atTime priority) so callers like Aggregator that read `e.source` directly keep working. Single-row clusters trivially have one source; multi-row clusters expose the "primary observer" while leaving the full set on `rec.sources` and per-field detail on `rec.provenance`.
  - **`Research/Lifecycle.lua`** — `rowsForItem` switches from raw `Query` to `Reconcile`. Cohort construction was the most visible duplication site: a deposit + sale pair captured by both Native and Journalator yielded two cohorts (one greedy-consumed each sale row), inflating posting counts on every items page in the UI. Reconciled records carry the same fields (atTime, kind, copper, count, charKey, meta, id) so the rest of the file is unchanged.
  - **`Research/Aggregator.lua`** — `augmentTxnsFromLedger` and the two `ah-fee` sweeps switch to `Reconcile`. `record.sales` / `record.purchases` / `record.failures` now contain one entry per real-world event; `profitSummary` / `salesSummary` / `purchasesSummary` totals stop multiplying by source count. The `ah-fee` sweep is single-source today (Native only) so the change is structural — pass-through clusterwise — but picks up automatically the moment a second adapter produces fees.
  - **`UI/LedgerPage.lua`** Reconciled/Raw mode toggle. Default is Reconciled (the everyday correct view). Raw preserved for power-user debugging — answer "which adapter saw which row" when triaging a discrepancy or filing a Compare-tab follow-up. Mode persists across sessions via `TallyDB.ui.ledgerMode`. Refresh + Export branch on mode: Reconciled walks `Ledger:Reconcile(query)` with inline income/expense/net since `Ledger:Stats` hits raw `Query`; Raw uses `Query` + `Stats`. Source column in Reconciled shows the primary source plus a "+N" suffix for additional contributors so multi-source clusters are visible at-a-glance. Reconciled exports emit the source column as a plus-joined list ("native+tsm+journalator") for plain-text readability. ScrollTable's source column gets a `_sortSource` override so the "+N" annotation doesn't break alphabetic sort by primary source.
- **TLY-31 Phase B + TLY-45 — sibling backfill stance, session log, divergence reporter.** Phase 4.
  - **Session-window log (`Ledger.lua`).** `TallyDB.sessions` is a bounded ring (200 entries) of `{ startedAt, lastSeenAt, build, version, charKey }` records. Opened on `PLAYER_LOGIN` via `Ledger:StartSession`; extended every 60s by a heartbeat ticker calling `Ledger:HeartbeatSession`. `SessionForTime(t)` returns the session whose `[startedAt, lastSeenAt + 90s grace]` window covers t — grace covers events between the last heartbeat and a late-arriving capture. `SessionCoverage(from, to)` reports total sessions + windows + observation-seconds in a range, used by the divergence header for "Tally observed X% of last week" framing.
  - **Divergence reporter (`Ledger.lua`).** `Ledger:DivergenceReport(filter)` walks Reconcile clusters and bins source-disagreements into real-gap (sibling has the event, Native didn't, atTime fell inside a session window — the bug class), expected-gap (sibling has the event, Native didn't, atTime outside any session — backfill is the truth), field-disagreement (multiple sources captured the event but disagree on copper / atTime / count / itemKey — Reconcile already picks; this counts so we know how often it happens). Unknown-kind rows skip reconciliation by design — each carries a distinct sourceKind, merging would lose the diagnostic. Summary header carries cluster counts + per-source contribution totals so consumers can frame the report ("TSM contributed 4327 rows, Native 891") without a second pass.
  - **Periodic ticker rewire (`Core.lua`).** The 5-minute auto-import `NewTicker` is removed. Sibling adapters are imported once at `PLAYER_LOGIN` (existing one-shot, unchanged) and re-importable from Settings's per-source "Import now" buttons; no recurring re-pull. Replaced with a 60s heartbeat ticker (extends current session's `lastSeenAt`) and a one-shot 60s post-login `DivergenceReport` that silently emits a one-line chat hint when `realGapCount > 0` ("Tally: divergence check — N real gaps. /tally diag divergence to inspect.") and stays out of the way when zero.
  - **`/tally diag divergence` (`Core.lua`).** New slash sub-command that opens the divergence report in Cogworks's `CreateCopyDialog`. Format covers session header, source contribution counts (alphabetized for cross-tester diff stability), full list of real gaps (always actionable), and the first 25 each of expected gaps + field disagreements (truncated for sanity, full counts in header). Falls back to chat dump if Cogworks copy dialog is unavailable. Bonus: per the alpha10 debug-UX directive, `/tally diag` default switches from chat dump to copy dialog. `/tally diag chat` preserves the inline-printing behavior for users who want it. `/tally diag copy` becomes a no-op alias for the new default to avoid breaking earlier alpha muscle memory.
  - **Setup wizard wording (`UI/SetupWizard.lua`).** "Import" → "Backfill" wherever the verb refers to sibling-source data acquisition. Sources step explicitly frames sibling adapters as backfill recovery and Tally's native source as the live capture. Backfill step note rewrites the "re-imports every 5 minutes" line — that's no longer true, replaced with the manual Import-now path + a `/tally diag divergence` pointer. Finish button: "Finish & Import" → "Finish & Backfill". `MultiProgress` panel title "Importing your data" → "Backfilling your data". Completion message "Import complete" → "Backfill complete".
  - **Settings page (`UI/SettingsPage.lua`).** Header note above the per-source rows reframes the section without renaming the buttons (Import now stays — familiar muscle memory). Note explicitly contrasts sibling backfill with Native's live capture so users don't expect TSM rows to update without clicking through.

## [v0.1.0-alpha8]

Alpha8 ships the Phase 1 slice of the planned authoritative-ledger bundle (data-quality + diagnostic surface — TLY-36 / TLY-37 / TLY-38) plus a stack of tester-feedback fixes against the Phase 1 + alpha7 surface. Phases 2–4 of the bundle (TLY-29 capture-layer rigor, TLY-30 Authority / Reconcile API, TLY-31 Phase B sibling-adapter demotion) shift to alpha9 — calling this rev now per direct user direction so testers can validate Phase 1 in the wild and cycle on the polish fixes before the bigger workstream starts.

- **TLY-36 — itemID resolution at adapter source.** `Sources/Native/AHInvoice.lua` now resolves itemID from itemName via `GetItemInfoInstant` for sale / purchase / ah-fee rows, with a per-session `itemNameCache` (false-sentinel for legitimately-unresolvable names so we don't keep paying the lookup cost across many invoices). Both the main entry and the companion fee entry get itemID + itemKey populated. `Sources/FlipQueue.lua` `mapEntry` adds a fallback chain — `itemIDFromKey(itemKey)` → `entry.itemID` → `GetItemInfoInstant(entry.itemLink)` — so FQ rows with malformed item keys but a valid direct itemID or itemLink resolve cleanly. New skip counters `invoice_no_item_id` (Native) and `bad_item_key` (FlipQueue) increment per row that falls all the way through; both surface in `/tally diag` SkipCounters automatically. Precondition for TLY-37: comparable `meta.name` on both Compare sides.
- **TLY-37 — Compare matcher `name` tier fallback.** `Ledger.lua` adds a secondary index keyed by `(charKey, lower(meta.name))`, populated for any entry whose name is non-empty. New `name` match tier between `loose` and `fuzzy` — fires when the primary `(charKey, itemID)` index has no match for an A-row that has no itemID but does have a name. The name-index match window matches `LOOSE_WINDOW` (±5 min). `UI/CompareLedgersPage.lua` `TIER_COLOR` map gains `name = "|cffffb050"` (amber, between loose's gold and fuzzy's orange) and the matches summary line includes the new column. Fix path for the "ledger has nil-itemID native rows that can't bucket against itemID-bearing TSM / FlipQueue rows" failure mode that dominated tester divergence reports.
- **TLY-38 — Compare export rework.** Per-row format gains source + kind columns: `[A-only] 03/12 00:03 | flipqueue | ah-cancel | Flipron-Maelstrom | item:? | 0c`. Walks `pairs_out` twice — top-5 A-only, top-5 B-only — instead of the previous single-pass top-10 mix; guarantees a useful sample on both sides even when divergence is heavily lopsided. After each side's per-row sample, prints bucket-count summaries: `A-only by kind: ah-cancel=180, ah-expire=104, sale=27, …` and `… by source: flipqueue=290, tally-native=41`. New "Hide expire/cancel in export" checkbox skips rows where `copper == 0` from both the sample and the bucket counts; default off so first-time exporters see the full picture.
- **TLY-40 — warband bucket no longer duplicates per BagCacheUpdate.** Pre-fix: every BagCacheUpdate / AuctionsCacheUpdate scheduled `RefreshCharacter`, which passed the existing `rollup.warband.items` table straight back into `projectCharacter` as the spill destination — the character's warbound items were re-folded into the same shared map without any compensating subtraction, so each refresh added without removing. Tester report: a single Master of Fishing in bags became 2 / 3 / 4 within seconds of bag activity. `Inventory/Ownership.lua` restructures `rollup.warband` to track warbank contents and per-character spills separately: `{ gold, bankItems, spillsByChar = { [charKey] = items }, items }` where `items` is the merged view. `projectCharacter` returns its spilled items as a separate map alongside `items`; `projectWarbandBank` returns just the bank. New `recomputeWarbandItems` helper rebuilds the merged view after any input change. `RefreshCharacter` replaces `spillsByChar[charKey]` wholesale (the wholesale replacement is what fixes the bug — old contribution dropped, new contribution stands alone) then recomputes. The public `rollup.warband.items` field keeps the same shape so no consumer changes (Inventory page, NetWorth, Research, Lifecycle). Migration on first `:Get` after upgrade: rollups missing `warband.bankItems` trigger a forced `Rebuild`. Plus a deferred `Rebuild` 5s after `PLAYER_LOGIN` (mirrors the TLY-21 sibling-source backfill defer pattern) so the migration completes without manual `/tally rescan` even if the first `Get` lands before Syndicator's API is populated.
- **TLY-41 — Compare export to copy dialog.** `exportBtn` `OnClick` now accumulates output into a string buffer and hands it to `Cogworks:CreateCopyDialog` (same primitive `/tally diag copy` uses) instead of `print`-ing to chat. The chat frame mangled the post-TLY-38 multi-section dump (long lines wrapped, history dropped past the buffer, selection-for-paste fiddly in the WoW chat window). Falls back to chat `print` when `Cogworks.CreateCopyDialog` is unavailable. Button text drops the "to chat" qualifier — just *Export*. Plus a no-default-selection change to the Compare tab: `state.sourceA` and `state.sourceB` start nil, dropdowns show `(pick a source)`, no Compare runs until both are picked. Pre-fix the tab eagerly ran `Tally Ledger (all)` vs the first real source on tab open, kicking off an expensive Compare (now even heavier with the TLY-37 name index pass) before the user had any signal Tally was working.
- **TLY-42 — tab strip overlap.** Cogworks's `ThemedMainFrame` summary bar anchors to `titleBar BOTTOMLEFT/BOTTOMRIGHT`. Tally hides the sidebar slot and re-anchors `frame.content` directly under the title bar, mounting `cw:CreateTabPanel` there — so the summary bar's anchor and the tab strip's leftmost-tab anchor are identical. The `frame:SetSummary("— " .. key)` call on every tab change rendered the active tab name as plaintext overlapping the NetWorth tab. `UI/MainFrame.lua` `onTabChange` no longer calls `SetSummary`; tabs are the active-page indicator. Comment flags the cogworks-side follow-up: the primitive needs an "only when sidebar shown" or anchor-aware mode for consumers using tab-strip layouts.
- **TLY-43 — Ledger tab Export button.** `UI/LedgerPage.lua` adds an *Export* button to the filter row (right-anchored, with the entry-count text re-anchored to its left). On click: re-runs `Ledger:Query` and `Ledger:Stats` for the active filter chip, sorts by `atTime` descending with no row cap (the on-screen `MAX_ROWS=500` cap is for ScrollTable rendering performance; the export is for analysis where capping is actively unhelpful), builds a paste-ready buffer with header + totals + one row per transaction (`MM/DD HH:MM | charKey | kind | source | item | amount`), hands to `Cogworks:CreateCopyDialog`. Falls back to chat `print` when the lib is missing.
- **TLY-44 — Compare tab clears selection on every show.** `page:HookScript("OnShow", …)` resets `sourceA` / `sourceB` to nil, both dropdowns to the `(pick a source)` placeholder, summary text + scrollTable rows cleared, `lastPairs` / `lastStats` reset. Pre-fix: re-entering the tab with a previous A/B still selected re-ran the full Compare from scratch — non-trivial work on large datasets. Same UX principle as the no-default part of TLY-41: Compare is a power-user surface (gated behind Settings, default off), so the one-extra-click cost on re-entry is the right trade for an instantly-responsive tab.
- **CI: reusable verify-package gate.** `.github/workflows/release.yml` gains a `verify` job that calls cogworks's reusable `verify-package.yml` workflow ([COG-27](https://github.com/gezmodean-wow/cogworks/issues/27)) with `release: needs: verify` so a packaging regression blocks upload to CurseForge / Wago. Asserts TOC integrity, XML reference resolution, and non-empty `externals` directories — the failure modes that produced the alpha6 "Libs/Cogworks-1.0/Cogworks-1.0.xml missing" report (TLY-39's underlying cause was a different bug; the verify gate covers the original-suspicion class).

## [v0.1.0-alpha7]

- **TLY-39 hotfix.** Bumped Cogworks external in `.pkgmeta` from `v0.13.0` → `v0.13.1` to pick up [COG-26](https://github.com/gezmodean-wow/cogworks/issues/26) — the v0.13.0 `ThemedMainFrame` ESC handler used `OnKeyDown` to drive close-on-escape, which tainted Blizzard's secure `ToggleGameMenu` path. Players hit `ADDON_ACTION_FORBIDDEN AddOn 'cogworks' tried to call the protected function 'ClearTarget'` after a single open/close of Tally's main window; the next ESC press was silently swallowed and the game menu / logout / quit dialog stopped working until `/reload`. Tally is the only currently-shipped cog that calls `cw:CreateThemedMainFrame`, making it the live attack vector for COG-26 in the wild even though every cog vendoring v0.13.0 carries the broken primitive. Cogworks v0.13.1 ships the fix using `UISpecialFrames` registration instead of `OnKeyDown` — Blizzard's standard ESC-to-close mechanism, which doesn't taint the secure path. No Tally code change required: `UI/MainFrame.lua` already passes `name = "TallyMainFrame"` to `CreateThemedMainFrame`, which is exactly what the new `UISpecialFrames` registration consumes. Tagged as a hotfix on top of alpha6 per the cadence rule (alphas are full critical-path bundles or tester-reported hotfixes between bundles); the planned authoritative-ledger bundle (TLY-29 / TLY-30 / TLY-31 Phase B / TLY-36 / TLY-37 / TLY-38) moves from alpha7 to alpha8.

## [v0.1.0-alpha6]

- **TLY-33 hotfix.** Lua's `string.format("%d", N)` requires N to fit in a signed 32-bit integer (max ~2.1B copper / ~214,748g). Several `Sources/Native/*.lua` and `Sources/Journalator.lua` adapters built dedupe-hash strings via `%d` over copper amounts, throwing "integer overflow attempting to store …" the moment a tester with high-value posts triggered the path. Switched `%d` → `%.0f` everywhere a copper / money / price value flows through a format slot — `%.0f` accepts a Lua double and formats as a decimal integer with no fractional part, working up to 2^53 (~9 quadrillion). Fixed in `Sources/Native/AHPosting.lua` (post hash + cancel hash + debug print), `Sources/Native/AHInvoice.lua` (mail invoice + AH-fee hash), `Sources/Native/Vendor.lua` (vendor row hash), `Sources/Native/Repair.lua` (repair hash + debug print), `Sources/Native/Mail.lua` (mail receive / send hash + debug prints), `Sources/Journalator.lua` (eight salt constructions across invoice / posting / vendoring / trade / mail / taxi / quest / mission / loot / trading-post / crafting-order paths). The Journalator overflows are pre-existing — same root cause, same fix shipped together since both adapters were one tester report away from breaking on the same data shape.
- **FQ-138 cross-cog check.** Reviewed FlipQueue's recently-fixed FQ-138 ("FlipQueue interferes with TSM Post Scan, items get skipped") and confirmed Tally is non-interfering by construction. Tally's AHPosting bucket only uses `hooksecurefunc` (pure observation) and reads `C_AuctionHouse.GetOwnedAuctions()` (cache read). Tally never calls `RequestOwnedAuctionsRefresh()` and never listens for `AUCTION_HOUSE_AUCTION_CREATED`, which is what FQ's listener was extra-querying after every post — the source of TSM-state-machine confusion. No fix needed.

## [v0.1.0-alpha5]

- **Cogworks v0.13 adoption.** `.pkgmeta` external bumped from v0.11.0 → v0.13.0; vendored `Libs/Cogworks-1.0/` synced with the new `Debug`, `ThemedMainFrame`, `Drawer`, `Slash`, `Toast`, `SegmentedControl`, `Scaling` modules. Tally now leans on three new primitives:
  - **Debug toolkit** ([cogworks#25](https://github.com/gezmodean-wow/cogworks/issues/25), shipped in v0.13). `/tally diag` rewritten as 12 inspector functions registered with `cw:RegisterDebugInspector("Tally", ...)` — each section (Versions / Setup / Syndicator / Inventory / CurrentChar / WarbandProbe / Ledger / SkipCounters / History / DisabledSources / Siblings / Memory) is now a pure function returning a Lua table. The slash still chat-prints the same content as alpha4 but the data definition is a single source of truth used by both the chat dump and the new copy-friendly `/tally diag copy` (which opens `cw:CreateCopyDialog` with `cw:DumpDebugState("Tally")` output — structured Lua-table format, easier to diff between testers). `ns.dbg = Cogworks:RegisterDebugLogger("Tally", { enabled = TallyDB.debug })` exposes a logger that all the new Phase A bucket files call via `dbg:PrintDebug(...)` so tester sessions can flip the debug toggle and see real-time event-capture flow.
  - **`/tally debug` opens `cw:CreateDebugConsole({ cog = "Tally", savedvars = TallyDB.ui.debugConsole })`** — live console with status / actions / inspectors / profile / log tabs, persisted geometry. Replaces Tally's local `/tally diag` placeholder for the live-tester surface.
  - **`UI/MainFrame.lua` rebuilt on `cw:CreateThemedMainFrame`.** Replaces ~95 LOC of hand-rolled chrome (title bar, close button, resize bounds, drag-to-move, resize grip, ESC handler, persisted geometry, uiScale subscription). The primitive bundles a sidebar slot which Tally hides — the existing `cw:CreateTabPanel` UX is preserved by anchoring the panel directly into `frame.content`. Frame geometry storage schema bumped from `{ point, relPoint, x, y, size = { w, h } }` to ThemedMainFrame's `{ x, y, w, h }` BOTTOMLEFT-anchored format; existing testers will need to re-drag the frame once after upgrading.
  - **`/tally` slash dispatch migrated to `cw:RegisterSlashCommands`.** Removed `printHelp`, `handleSlash`, and the `SLASH_TALLY1/2 + SlashCmdList["TALLY"]` boilerplate (~110 LOC). Each subcommand is now a `{ name, run, help, args, aliases }` record; auto-help renders from those fields. `/tally help` and unknown subcommands route through the lib's auto-help. Behavior identical: same 14 subcommands + same aliases as alpha4.
