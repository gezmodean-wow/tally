# Changelog

All notable changes to Tally will be documented in this file.

## [Unreleased]

- New `/tally diag` (alias `/tally diagnostic`) prints a structured snapshot of Tally state to chat: addon + Cogworks + Interface versions, setup-completed + grandfathered flags, Syndicator detection (loaded? `GetAllCharacters` callable?), Syndicator's character roster (first 10), inventory rollup health (char count, item count, last-scan age, warband distinct items, list of any chars with 0 items), the current player's char vs Syndicator visibility + rollup presence, ledger row count + per-source breakdown, history snapshot counts (inventory + per-strategy pricing), disabled sources list, sibling-addon detection (TSM / FlipQueue / Journalator / Auctionator), `GetAddOnMemoryUsage("Tally")`. Designed for "tester reports a bug — please paste this." Tally-local pending Cogworks v0.13's debug primitive ([cogworks#25](https://github.com/gezmodean-wow/cogworks/issues/25) closed in favor of v0.13). `ns.Diag` exposed for sibling cogs.
- Main frame is now resizable (drag the bottom-right grip). Bounds 600×360 to 1600×1100; size persists across sessions in `TallyDB.ui.mainFrame.size`. `OnSizeChanged` throttles `RefreshActivePage` to once every 0.1s while sizing so charts / ScrollTables / column widths recompute live without burning frames. Tester report: Compare tab's table is wider than the default frame width, so users couldn't scroll horizontally to see the rightmost columns.
- Compare view gains a `Tally Ledger (all)` virtual source. New `Ledger.PSEUDO_SOURCE_LEDGER` ("__ledger") routes through `Ledger:Compare` to a `Query()` with no source filter — returns every entry from every adapter. Default selection on opening the Compare tab is now `Tally Ledger (all)` vs the first real source, so the question "would re-importing pull anything new in?" is the immediate framing instead of "which two sources do I want to diff." Tester report: comparing TSM vs `tally-native` only ever showed TSM's data because the Native adapter only writes mailbox-event rows, which the user hadn't generated yet.

## [v0.1.0-alpha3]

- First-run setup wizard (TLY-25). Six-step flow built atop the new Cogworks v0.11.0 `cw:CreateWizard` primitive: welcome, source detection (live row counts per registered source with per-source enable/disable), concept primer (Net / Owned / Warband cards live-valued from the user's actual bag), strategy picker (4 TSM presets each shown side-by-side with the bag's value under it — resolves the TSM-mismatch question from TLY-24 in the wizard itself), history cadence config, and backfill kickoff with three pace presets (Gentle 200rows/0.5s, Balanced 500rows/0.2s, Aggressive 2000rows/0.05s). Auto-shows on the first PLAYER_LOGIN where `inventoryRollup` is missing AND a non-Native source is detected; skipped for upgrading users. Re-runnable via `/tally setup` or Settings → "Re-run setup wizard".
- Chunked import driver (TLY-25). `Ledger:ImportFromAllSourcesChunked(opts)` walks registered sources sequentially, processing each via the new `getEntriesFn` adapter contract that returns parsed entries instead of inserting inline. The driver yields between batches via `C_Timer.After` chains; chunkSize and delaySec are tunable. Existing `importFn` synchronous path preserved for callers that need the all-at-once behaviour. Native source stays event-driven (no chunking needed). New `UI/ProgressBar.lua` widget (Tally-local pending [cogworks#23](https://github.com/gezmodean-wow/cogworks/issues/23)) shows live `Importing TSM: 47,231 / 90,128 (52%)` while playing.
- Item lifecycle module + drill-down page (TLY-26). New `Research/Lifecycle.lua` synthesizes ledger rows into per-item posting cohorts: each cohort is one AH listing, paired with the eventual sale rows / expire / cancel within a 30d window on `(charKey, itemID, count)`. For users without Journalator (no `ah-deposit` data), synthetic single-row cohorts are produced so the view degrades gracefully — with a UI hint to install Journalator for full coverage. Cost-basis attribution computed at query time in two methods: FIFO (oldest unconsumed purchase units consumed first against sales) and weighted-average (rolling avg cost across all open inventory). Insights surfaced on the new Lifecycle tab: postings count, sold/failed split, total revenue, fees + deposit forfeits, avg time-to-sell, best/worst list price, pricing trend (linear-fit over the buyout series — improving / declining / flat). Click any cohort row for a drill-down detail panel showing the paired sale rows, fees, deposit forfeit, and cost basis. Reachable via `/tally lifecycle <item>` or the new "View lifecycle →" button in the Research panel.
- Multi-source ledger comparison view (TLY-27). New `Ledger:Compare(sourceA, sourceB, filter)` aligns rows from two sources via three fall-through tiers — strict (`(charKey, itemID, count, copper)` ±60s), loose (`(charKey, itemID, count)` ±5min), fuzzy (`(charKey, itemID)` ±1h) — and surfaces the diff in a debug-oriented Compare tab gated by a Settings toggle (default off). Top-of-page summary card shows row counts per side, gross-copper totals, delta, and tier breakdown (`X strict, Y loose, Z fuzzy, A in A only, B in B only`). Two-column scroll table renders aligned pairs with per-row Δ. Export-to-chat button prints a paste-ready debug block of the top-10 unique-on-each-side rows for filing into TLY-24-style mismatch reports. `/tally compare` opens it directly. Source A / Source B selectors work for any pair of registered adapters: TSM ↔ Native, Native ↔ Journalator, FlipQueue ↔ Journalator, etc.
- Journalator adapter (TLY-22). `Sources/Journalator.lua` reads from `Journalator.State.Logs` (live current month) plus every archived store opened via `Journalator.State.Archive:Open("SometimesLocked", "Logs-" .. ts)`. Maps 16 buckets — Invoices (sale + ah-fee), Failures (ah-expire / ah-cancel), Posting (ah-deposit), Vendoring (vendor-sell / vendor-buy), VendorRepairs (repair), Trades (trade), BasicMailReceived (mail-receive), BasicMailSent (mail-send), Taxis (taxi), TrainingCosts (trainer), Questing (quest-reward), MissionTables (mission), LootContainers (loot), TradingPostVendoring (trading-post), CraftingOrdersPlaced (crafting-order-placed), Fulfilling (crafting-order-fulfilled). Coexists with Native / TSM / FlipQueue per the TLY-19 plan: imports unconditionally; Tally never auto-disables sibling sources. Stable hash IDs `(bucket, realm, char, time, salt)` make re-imports deterministic.
- Ledger schema extensions (TLY-23). `Ledger.Kinds` adds `AhDeposit` (sign 0; paired with sale/expire/cancel at view time by Lifecycle), `Taxi` (-1), `Trainer` (-1), `QuestReward` (+1), `Loot` (+1), `Mission` (+1), `TradingPost` (-1), `CraftingOrderPlaced` (-1), `CraftingOrderFulfilled` (+1). Updated `KindSign` honors all new kinds. View-time pairing of `ah-deposit` against subsequent `sale`/`ah-expire`/`ah-cancel` lives in `Research/Lifecycle.lua`; the canonical entry preserves gross deposit + meta (buyout / bid / count) for downstream tooling.
- User-level source enablement. New `Ledger:SetSourceEnabled(name, enabled)` and `IsSourceEnabled` honor a user opt-out list persisted at `TallyDB.disabledSources`. The setup wizard's source-detection step writes here; `IsSourceAvailable` now respects user opt-out as well as runtime detection. Disabled sources cleanly skip the chunked import flow.
- `_G.TallyAPI` bumped to v1.5: adds `GetItemLifecycle(itemID, opts)` and `CompareLedgerSources(a, b, filter)` for sibling cogs.
- Slash additions: `/tally setup` (re-run wizard), `/tally lifecycle <item>` (or `/tly lc`) (open per-item drill-down), `/tally compare` (open the multi-source comparison view).
- Cogworks pin bumped from v0.10.0 → v0.11.0 in `.pkgmeta` to pull in `CreateWizard`. Vendored `Libs/Cogworks-1.0/` synced to v0.11.0 contents.
- Performance overhaul (TLY-21). Reports of 15-20fps + multi-GB memory use traced to four hot paths firing on every Syndicator cache event:
  - **Re-import storm killed.** `Ledger:ImportFromAllSources` no longer runs on `InventoryChanged`. Sibling-source backfill (FlipQueue / TSM) was previously walking megabytes of CSV strings on every bag-slot change. New cadence: once at PLAYER_LOGIN (deferred 5s so login isn't blocking) + a 5-minute periodic ticker + manual "Import now" buttons in the Settings panel. Native source stays event-driven via `MAIL_INBOX_UPDATE` so live AH activity still flows in.
  - **Ledger sort dropped.** `Ledger:Insert` and `Ledger:InsertMany` no longer call `table.sort` over the whole entries list — bulk imports of N rows were O(N² log N). Storage is now append-only; consumers that need chronological order sort the result of `:Query()` themselves (LedgerPage's table renderer already sorts at render time, so the user-visible sort is unaffected).
  - **Ownership rebuild debounced + scoped.** `BagCacheUpdate` / `AuctionsCacheUpdate` now refresh just the current character's bucket via new `Ownership:RefreshCharacter`; `WarbandBankCacheUpdate` only refreshes warband via `Ownership:RefreshWarband`; full `:Rebuild` only on Syndicator's one-time `Ready`. All four are coalesced behind a 0.5s debounce so a single looting interaction doesn't trigger 5+ rebuilds.
  - **History defaults tightened.** Default retention 365d → 90d, daily-rollup-after 30d → 7d, min interval 6h → 12h. Auto-migration: users still on the legacy defaults get bumped to the new ones at next login; users who set their own retention/cadence keep theirs. A one-shot prune at PLAYER_LOGIN trims existing bloated history immediately.
- UI primitive sweep — Tally now leans on Cogworks-1.0 widgets instead of hand-rolling its own. Pass 1:
  - **Main frame** uses `cw:CreateTabPanel` for the page strip; old hand-rolled tab buttons + `rebuildTabStrip` are gone. Pages register via `MainFrame:RegisterPage(name, fn)` as before; the panel is constructed lazily on first `:Show()` once all four pages are present. New `MainFrame:RefreshActivePage()` lets event handlers re-fire the open page's `Refresh` without going through `ShowPage` (which is now a no-op when the requested tab is already active).
  - **Ledger page** uses `cw:CreateScrollTable` for the transaction list — sortable headers (click to flip direction), drag-resizable column widths, suite-consistent chrome. Default sort is newest-first; the column row pool + manual scroll frame are gone. Filter chips above the table stay hand-rolled until [cogworks#19 (segmented control)](https://github.com/gezmodean-wow/cogworks/issues/19) lands.
  - **Research page** ownership table + per-realm P&L table both swap to `cw:CreateScrollTable`. Both gain sortable, drag-resizable columns. Default sorts: ownership descending by quantity; P&L descending by net (toggle to ascending for biggest losses).
  - **Settings page** action buttons (`Take snapshot now`, `Clear all history`, per-source `Import now`) route through `cw:CreateButton` when Cogworks is loaded, falling back to `UIPanelButtonTemplate` otherwise.
  - Three Cogworks primitive requests filed for the gaps still hand-rolled in Tally: [cogworks#19 segmented control](https://github.com/gezmodean-wow/cogworks/issues/19), [cogworks#20 CreateSettingsInput validate+suffix+flash](https://github.com/gezmodean-wow/cogworks/issues/20), [cogworks#21 CreateSectionHeader rule + flexible anchor](https://github.com/gezmodean-wow/cogworks/issues/21). Tally tracks them in TLY-15 and will migrate the remaining hand-rolled bits once they ship.
- Warbound items now belong to the warband, not the holding character (TLY-16). `Inventory/Ownership.lua` classifies each slot's bind type via `GetItemInfo` (types 7/8/9 = warbound, cross-checked against FlipQueue's classifier). Warbound items sitting in a character's bags / personal bank / mail / reagent / auctions route into `rollup.warband.items` instead of that character's bucket. Equipped + void slots are exempt — a "Warbound until equipped" item that's been equipped stays with the character. Warbank tab contents continue to roll up to Warband (no regression). Bind classification is cached per itemKey so the same item resolved across many slots costs one `GetItemInfo` call.
- Richer Research context — TSM group, Auctionator lists, FQ todos, per-realm P&L:
  - **TSM group lookup** — new `Pricing:GetTSMGroupPath(itemID)` resolves an item's TSM group path via `TSM_API.GetGroupPathByItem`, with bare item-ID fallback for bonus-ID variants. Surfaces in the research record as `record.tsmGroup` (e.g. `Flipping/Herbs`).
  - **Auctionator shopping list memberships** — when Auctionator is installed, walks `AUCTIONATOR_SHOPPING_LISTS` and finds lists containing the item by name. Stored on `record.auctionatorLists`.

  - **Research panel** gains a context line under the item header showing Auctionator list memberships, FQ todos, and active-auction count when present (hidden if all three are empty). Right column of the body now shows `PER REALM (P&L)` table — REALM / SOLD / BOUGHT / NET — replacing what was a single full-width ownership area; `WHERE IT LIVES` lives on the left half. Item-header sub-line now also shows the TSM group when set.

- Historical net-worth replay (TLY-005):
  - Inventory snapshots now also record per-character (and warband) gold totals, so historical net-worth replay can sum gold + items at any past timestamp.
  - Inventory snapshot schema bumped from `[charKey] = { bags=N, ... }` to `[charKey] = { saleable, total, locations = { bags=N, ... } }`. The saleable/total pair preserves the bound-vs-saleable signal that per-location counts can't reconstruct alone.   - `_G.TallyAPI` (v1.0) exposes `GetItemResearch`, `InvalidateItemResearch`, `GetNetWorthSnapshot`, `GetInventoryRollup`. Versioned stopgap until Cogworks issue #6 lands a native API registry.
  - Slash command: `/tally research <itemlink-or-id>`.
- Fixes (post initial smoke-test):
  - `Util/Items.lua` — lifted FlipQueue's canonical `ParseItemLink` + `MakeItemKey` so Tally's rollup and research lookups produce identical keys, and battle-pet links resolve correctly. Deletable once cogworks#6 lands and Cogworks owns these helpers.
  - `Inventory/Ownership.lua` — rewrote container walker to match FlipQueue's `Scanner.lua` patterns: bags `[1..5]` flat slot arrays, bank tabs with `tab.slots or tab` heuristic, warband bank with the same heuristic. Warband items now actually appear in the rollup.
  - `Research/Aggregator.lua` — link normalization uses `Util/Items` so links match rollup keys; bare item IDs aggregate across bonus-ID variants; pet records skip TSM pricing; chat output now lists per-character/warband locations so warband visibility is verifiable.
- Net worth = saleable items only:
  - Inventory rollup tracks both `total` and `saleable` counts per item (saleable = Syndicator's `isBound` flag is false; WoW Tokens are special-cased as always saleable).
  - `NetWorth:Snapshot()` defaults to saleable-basis. `Snapshot({ includeBound = true })` returns the owned-worth view.
  - `/tally ownedworth` (alias `/tly ow`) prints the owned-worth view alongside `/tally networth` for the saleable view.
  - LDB tooltip surfaces both — header reads "net worth (saleable items only)" with a separate "Owned worth (incl. bound)" line.
  - Research record adds `saleableInventory` and `valuation.ownedWorthContribution`; `valuation.netWorthContribution` is now strictly saleable. `totalInventory` keeps its FlipQueue-compatible meaning (everything owned).
